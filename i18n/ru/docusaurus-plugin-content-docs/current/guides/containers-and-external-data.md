# Несколько и внешние контейнеры {#multiple--external-containers}
:::note
Начиная с версии 3.2.58 можно создавать до 128 контейнеров для одного приложения; раньше — до 3. Одно приложение можно одновременно запускать с разными контейнерами во всех экземплярах LiveContainer.
:::
:::note
Большинство приложений не поддерживает контейнеры на внешнем хранилище и, скорее всего, будет вылетать.

Если внешняя папка станет недоступна, контейнер тоже будет недоступен до восстановления доступа.
:::

Несколько контейнеров позволяют хранить полностью раздельные, изолированные данные одного приложения.

Внешние контейнеры позволяют сохранять данные приложения вне LiveContainer. Это удобно, если вы хотите:
- управлять файлами приложения через файловый менеджер, пока приложение работает в LiveContainer;
- сохранять доступ к контейнеру, даже если приложение переведено в общий режим.

## Открытие настроек контейнера {#open-container-settings}

1. Удерживайте карточку приложения в LiveContainer.
2. Нажмите `Settings`.
3. Перейдите к разделу `Container`.

## Создание нескольких контейнеров для одного приложения {#create-multiple-containers-for-one-app}

### Создание контейнера {#create-a-new-container}

1. Нажмите `New Data Folder`.
2. Введите отображаемое имя.
3. Подтвердите создание.

Контейнер будет добавлен к приложению.

### Выбор контейнера при запуске {#switch-container-when-launching}

Если у приложения несколько контейнеров:

1. Удерживайте карточку приложения.
2. Откройте список `Containers` в контекстном меню.
3. Выберите нужный контейнер.

### Контейнер по умолчанию {#set-default-container}

1. Откройте нужный контейнер в настройках приложения.
2. Нажмите `Set Default Container`.

Этот контейнер будет использоваться при нажатии `Run`.

## Добавление внешней папки данных {#add-an-external-data-folder}

1. В настройках приложения нажмите `Select External Data Folder`.
2. Выберите папку в системном диалоге выбора файлов.
3. LiveContainer подключит её как контейнер.

## Операции с контейнером {#container-operations}

Для управления контейнером откройте страницу его настроек.

- `Container Name`: меняет только отображаемое имя в LiveContainer, не переименовывая папку на диске.
- `Container Folder Name`: реальный идентификатор папки контейнера. Используйте его для проверки точных путей и поиска данных. В настройках приложения это поле доступно только для чтения.
- `Isolate App Group`: перенаправляет пути контейнеров App Group гостевого приложения в изолированную область этого контейнера вместо общей папки App Group.
- `Spoof Identifier For Vendor`: создаёт и сохраняет постоянное подменное значение `identifierForVendor` для контейнера. Это помогает разделить идентификационные данные между контейнерами в приложениях, использующих `identifierForVendor`.
- `Set Default Container`: назначает контейнер используемым по умолчанию при нажатии `Run`.
- `Open Data Folder`: открывает папку данных контейнера для ручного импорта, экспорта или просмотра файлов.
- `Unbind`: убирает контейнер из списка контейнеров приложения, сохраняя его файлы на диске.
- `Delete Data`: удаляет файлы внутри контейнера, сохраняя сам контейнер.
- `Clean Keychain`: удаляет связанные с контейнером данные связки ключей.
- `Remove Container`: удаляет контейнер вместе с его папкой.

## Ограничения и особенности {#limits-and-behavior}

- Максимум `128` контейнеров на приложение; ограничение связано с числом групп доступа к связке ключей.
- Если контейнер используется работающим экземпляром LiveContainer, операции удаления блокируются.
