Обзор архитектуры LiveContainer

LiveContainer — не просто оболочка, а небольшая среда выполнения, которая запускает произвольные приложения iOS внутри своей песочницы, поддерживает внедрение твиков, многозадачность и работу без JIT. Здесь описаны структура современной кодовой базы и процесс запуска гостевых приложений.

Структура проекта​

Основной исполняемый файл (LiveContainer)​

  • Точка входа всей платформы. Выполняет начальную настройку, управляет данными и жизненным циклом контейнеров, запускает экземпляры LiveProcess для гостевых приложений.
  • Пока гостевое приложение не запущено, показывает интерфейс SwiftUI (LiveContainerSwiftUI).

LiveContainerSwiftUI​

  • Интерфейс на SwiftUI, созданный при участии @hugeBlack.
  • Содержит ресурсы локализации (Localizable.xcstrings). Помочь перевести строки можно в проекте Crowdin.

LiveProcess​

  • Лёгкий вспомогательный исполняемый файл с загрузчиком гостевых приложений. Использует те же entitlements, но другой идентификатор пакета, что позволяет поддерживать многозадачность и включать JIT по PID.
  • Изменяет бинарный файл гостевого приложения, настраивает dyld, внедряет твики и передаёт управление точке входа приложения.

MultitaskSupport​

  • Реализует плавающие окна внутри приложения и интеграцию с системными окнами iPadOS.
  • Обменивается данными с основным контейнером для синхронизации состояния приложений и маршрутизации ввода между экземплярами LiveProcess.

Вспомогательные компоненты SideStore​

  • Интегрируют API продления подписи и JIT в SideStore. Обеспечивают фоновое обновление сертификатов, обновление источников и обработку схем URL для установок через SideStore.

TweakLoader​

  • Минимальный загрузчик Substrate, поставляемый с LiveContainer.
  • Внедряется в каждое гостевое приложение новой командой загрузки. Его можно заменить через символическую ссылку TweakLoader.dylib.

ZSign​

  • Встроенное средство подписи, основанное на zhlynn/zsign через Feather.
  • LiveContainer поддерживает собственную ветку, адаптированную к своим entitlements и работе с несколькими контейнерами.

Сторонние библиотеки​

  • fishhook, litehook и OpenSSL подключены как подмодули Git. Они обеспечивают низкоуровневый перехват вызовов и криптографические функции загрузчика и средства подписи.

Принцип работы​

Подготовка исполняемого файла гостевого приложения​

  • Сегмент __PAGEZERO изменяется (vmaddr = 0xFFFFC000, vmsize = 0x4000), чтобы бинарный файл можно было отобразить в память LiveProcess.
  • Тип Mach-O меняется с MH_EXECUTE на MH_DYLIB.
  • Внедряется команда загрузки TweakLoader.dylib до вызова UIApplicationMain.

Подмена @executable_path​

  • Современные сборки перехватывают dyld4::APIs::_NSGetExecutablePath через litehook/fishhook.
  • Перехватчик вызывает исходную реализацию, разрешает запись в config.process.mainExecutablePath и подменяет путь, чтобы гостевое приложение находило ресурсы собственного пакета.
  • Старый способ на основе SIGSEGV больше не используется, но сохранён в документации основного репозитория.

Подмена NSBundle.mainBundle​

  • NSBundle.mainBundle переопределяется: API, запрашивающие метаданные пакета, получают пакет гостевого приложения вместо пакета LiveContainer.

Обход проверки библиотек и подписи кода​

  • При доступном JIT LiveContainer обращается к выбранному средству включения JIT для снятия проверок подписи исполняемого кода.
  • В режиме без JIT встроенный ZSign переподписывает гостевые приложения и твики сертификатом, импортированным из AltStore/SideStore.
  • Обход основан на Restoring Dyld Memory Loading.

Запуск приложения​

  • LiveProcess загружает изменённый бинарный файл гостевого приложения через dlopen.
  • TweakLoader загружает CydiaSubstrate и папки твиков этого приложения.
  • Загрузчик находит точку входа и передаёт ей управление; затем гостевое приложение обычным образом вызывает UIApplicationMain.

Несколько учётных записей и частичное разделение связки ключей​

  • Определены 128 групп доступа к связке ключей. Контейнеры выбирают группы случайным образом, чтобы уменьшить пересечения между приложениями и обеспечить раздельный вход в учётные записи.

Ограничения​

  • Entitlements гостевого приложения не копируются в основное приложение. Действуют только права, выданные самому LiveContainer.
  • Разрешения приложений, например доступ к камере и медиатеке, общие для всех гостевых приложений.
  • Контейнеры используют одну песочницу, поэтому вредоносное гостевое приложение может прочитать файлы другого.
  • Зарегистрировать расширения приложений нельзя: SpringBoard о них не знает, а число App ID ограничено.
  • В некоторых сценариях многозадачности не работает ввод с физической клавиатуры или через iPhone Mirroring.
  • Удалённые push-уведомления и запросы пользовательских схем URL часто не работают, поскольку LiveContainer не может зарегистрировать их в SpringBoard.
